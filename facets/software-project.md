# Software project

소프트웨어 코드와 설정이 구현 사실의 주요 정본인 환경을 보는 facet입니다. 코드만으로는 충분히 드러나지 않는 지식을 무엇으로 볼지 판단하는 데 도움을 줍니다.

## 이 관점에서 중요한 점

- 코드와 설정이 이미 충분히 표현하는 구현 세부사항을 OKF에 다시 소유하지 않습니다.
- 목적, 경계, 업무 규칙, 설계 의도처럼 구현만으로 오해 없이 알기 어려운 의미는 OKF에 내재화할 가치가 있습니다.
- 코드나 설정의 변경이 개념의 의미·조건·판단 기준을 바꾸면 관련 OKF에도 그 영향을 반영합니다.
- 파일·디렉터리 배치는 기존 저장소 관례와 실제 작업 방식에 맞게 판단합니다.

## 판단 질문

- 지금 기록하려는 내용은 코드나 설정이 이미 정본으로 충분히 표현하고 있는가?
- 구현 사실이 아니라 목적·제약·업무 의미·설계 판단을 설명해야 하는가?
- 이번 구현 변경으로 의미가 달라지는 OKF 개념이 있는가?
- 새 디렉터리나 문서를 만들기보다 기존 위치와 관례를 활용하는 편이 더 자연스러운가?
