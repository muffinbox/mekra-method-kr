# Large corpus

수백~수천 개의 PDF, 이미지 문서 또는 장기 축적 자료를 다룰 때 사용합니다. OKF는 모든 원문을 옮기는 공간보다 개념망, 핵심 요약과 탐색 경로의 역할을 강하게 가집니다.

## 권장 출발점

```text
repo/
├─ okf/
├─ sources/
├─ extracted/   # 선택
├─ docs/
└─ AGENTS.md
```

## 핵심 선택

- `sources/` 또는 외부 저장소가 원자료를 보존합니다.
- `okf/`에는 반복해서 쓰이는 핵심 개념, 관계, 판단 기준과 원자료로 가는 경로를 둡니다.
- 문서마다 반드시 OKF 항목을 만들지 않습니다. 독립적으로 설명하고 참조할 가치가 있는 개념을 기준으로 나눕니다.
- 낮은 빈도로 필요한 세부사항은 원자료에 남겨두고, 중요한 판단을 매번 원문에서 다시 조립하게 만드는 지식은 내재화합니다.

## extracted를 둘 때

추출 결과가 반복 사용되거나, 재생성 비용이 크거나, OCR·표·문단 구조에 수동 교정이 축적되는 경우 보존할 가치가 있습니다. 값싸고 결정적으로 재생성할 수 있다면 파이프라인만 보존하고 결과물은 만들 때마다 생성해도 됩니다.

품질은 원문 전체의 변환률보다 핵심 질문을 OKF에서 이해할 수 있는지, 답의 근거를 원자료까지 추적할 수 있는지로 판단합니다.

적용 후에는 새 원자료를 `sources/`에 넣을지 외부 저장소에 보존할지, 참조 위치와 식별자를 어디에 남길지 안내합니다. 추출물이 있다면 그 생성·갱신 방법도 연결합니다. 직접 작성한 새 지식의 위치와 자료 반영 요청 방법은 대상 README나 수집 안내에 남기고, 점진적 전환 중이라면 남은 자료 범위와 이후 처리 계기도 함께 설명합니다.

이 구성의 판단 근거는 [대량 자료의 지식 구성](../../okf/large-corpus.md)에 설명합니다.
